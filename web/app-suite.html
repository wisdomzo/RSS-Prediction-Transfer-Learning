Distributed Learning Guide

Run model training with a Dask scheduler and workers.

Use this setup when model training needs multiple workers. Prepare every worker computer first, start the scheduler on the master machine, then connect the workers before running Generate Model.

  • 1. Prerequisites

    Every participating computer must use a reachable network connection, a compatible Python environment, the project dependencies, and Dask Distributed. If ASSET cannot connect to the scheduler, training continues in single-machine mode.

    • All computers can reach the scheduler IP address on the LAN.
    • Firewall rules allow worker connections to port 8786.
    • Each worker has enough CPU cores and memory for its configured worker count.
  • 2. Install Dask Distributed on every worker computer.

    Run one of these commands on each worker machine before starting a worker process.

    python -m pip install "dask[distributed]" --upgrade
    conda install dask distributed -c conda-forge
  • 3. Confirm Dask is available on each worker.

    This check prints the installed Dask and Distributed versions. Use the same environment that will run the worker command.

    python -c "import dask, distributed; print(dask.__version__, distributed.__version__)"
  • 4. Increase the open-file limit on the master machine.

    Run this before starting Dask so many files and worker connections can stay open during training.

    ulimit -n 10000
  • 5. Start the scheduler on the master machine.

    Replace the IP address if your master machine uses a different LAN address.

    dask scheduler --host 192.168.1.200
  • 6. Start workers after the scheduler is running.

    Run one command per worker group. Adjust worker count and memory limit to match the available CPU and memory on each machine.

    dask worker tcp://192.168.199.1:8786 --nworkers 12 --nthreads 1 --name MacPro_alpha --memory-limit 14GB
dask worker tcp://192.168.199.1:8786 --nworkers 12 --nthreads 1 --name MacPro_beta --memory-limit 14GB
dask worker tcp://192.168.199.1:8786 --nworkers 6 --nthreads 1 --name MacPro_shan --memory-limit 14GB
  • 7. Run training from ASSET.

    Paste the scheduler address into Model Training / Scheduler, select feature vectors, then click Generate Model.

    tcp://192.168.199.1:8786
  • 8. Parameter reference.

    --host sets the scheduler bind IP on the master machine. The scheduler address is the tcp://IP:8786 endpoint that ASSET and all workers connect to.

    --nworkers is the worker count launched by that command. Higher worker count increases parallel jobs but also increases memory and file-handle pressure.

    --nthreads sets threads per worker. For CPU-bound training, 1 thread per worker is usually stable and predictable.

    --name gives each worker group a readable label, such as MacPro_alpha, so logs and Dask diagnostics can identify the machine.

    --memory-limit caps memory per worker process. Use it to avoid a single machine exhausting RAM during model training.
